# Техническое задание: обучающая банковская игра

## 1. Общие сведения

**Автор и инициатор:** Александр Ильин.  
**Целевая аудитория:** пользователи 14–22 лет, которым требуется практическое знакомство с финансовой грамотностью.  
**Формат продукта:** браузерная игра на Unity WebGL с сервером Kotlin/Spring Boot и PostgreSQL.  
**Назначение:** дать пользователю короткий учебный маршрут, проверить знания, разобрать ошибки и закрепить слабую тему повторным тестом; дополнительно дать безопасную практику операций на учебном рынке.

## 2. Границы первой версии

В первую версию входят регистрация, вход, онбординг, диагностика, тематические квизы, персональные уроки, повторение, профиль, учебная биржа, рейтинг и административные функции. Магазин реальных бонусов, ежедневные серии, отдельные мини-игры, восстановление пароля и подтверждение email относятся к дальнейшему развитию.

## 3. Функциональные требования

| ID | Требование | Критерий приёмки | Сценарий |
| --- | --- | --- | --- |
| FR-01 | Система должна позволять создать учётную запись по никнейму, email и паролю | Новый уникальный email создаёт игрока, пароль хранится как BCrypt-хэш, клиент получает JWT | US-02 |
| FR-02 | Система должна позволять войти и восстановить сохранённую сессию | Верные данные открывают главное меню; неверные возвращают ошибку; действующий JWT работает после перезапуска | US-03 |
| FR-03 | Новый игрок должен пройти онбординг и сохранить интересы | Информационные шаги доступны по порядку, интересы сохраняются в профиле, после завершения запускается диагностика | US-04 |
| FR-04 | Сервер должен создать диагностическую попытку без раскрытия правильных ответов | Клиент получает четыре темы и варианты ответов, но не получает `correctIndex` до отправки выбора | US-05 |
| FR-05 | Каждый ответ должен проверяться и сохраняться на сервере | Принятый ответ нельзя заменить; сервер возвращает правильность и объяснение | US-05, US-06 |
| FR-06 | Завершение квиза должно рассчитывать результат и награду | Незавершённая попытка отклоняется; повторный `finish` не начисляет очки ещё раз | US-05, US-06 |
| FR-07 | После ошибок система должна создать персональный урок по слабой теме | Урок содержит название, объяснение, пример и шпаргалку и принадлежит текущему игроку | US-07 |

| FR-10 | Профиль должен отображать учебные и игровые показатели | Отображаются никнейм, email, уровень, очки, интересы и стоимость портфеля | US-08 |
| FR-11 | Учебный рынок должен показывать акции, цены, историю и новости | Клиент получает состояние рынка, список акций, ценовую историю и последние новости | US-09 |
| FR-12 | Игрок должен выполнять операции BUY, SELL, SHORT и COVER | Валидная операция атомарно меняет деньги и позицию; невалидная не создаёт частичных изменений | US-09 |
| FR-13 | Система должна строить рейтинг по виртуальному капиталу | В рейтинге учитываются наличные и рыночная стоимость позиций, текущий игрок выделен | US-10 |
| FR-14 | Административные операции должны быть доступны только роли ADMIN | Игрок получает `403`; администратор управляет игроками, рынком и каталогом вопросов | US-11 |
| FR-15 | Пользователь должен безопасно завершить сессию | При выходе JWT удаляется, защищённые экраны закрываются, показывается стартовый экран | US-08 |

## 4. Нефункциональные требования

| ID | Требование | Проверка |
| --- | --- | --- |
| NFR-01 | Пароли не хранятся открытым текстом | Проверка `BCryptPasswordEncoder` и отсутствия пароля в ответах API |
| NFR-02 | Все игровые API, кроме `/auth/**`, требуют JWT | Запрос без токена получает `401` или `403` |
| NFR-03 | Игрок не может читать или изменять чужую попытку/урок | Интеграционный тест с двумя игроками |
| NFR-04 | Изменения схемы PostgreSQL выполняются Flyway-миграциями | Чистая БД поднимается с V1 и V2; Hibernate `validate` проходит |
| NFR-05 | Серверные тесты выполняются одной командой | `./gradlew test` завершается успешно |
| NFR-06 | Интерфейс не блокируется на время сетевых запросов | Есть состояние загрузки, повторный клик заблокирован, ошибка показана текстом |
| NFR-07 | Ключевой маршрут не должен терять уже подтверждённые ответы | Ответ сохраняется сервером до показа следующего вопроса |
| NFR-08 | Первая версия должна запускаться в современном браузере | WebGL проверен минимум в Chrome и Firefox при ширине 1280 и 1920 пикселей |
| NFR-09 | Секреты не должны находиться в GitHub | `.env` исключён, в репозитории находятся только примеры конфигурации |
| NFR-10 | Документация должна позволять новому разработчику запустить проект | README содержит зависимости, команды запуска и адреса сервисов |

## 5. Архитектурные ограничения

- Unity отвечает за интерфейс и взаимодействие, но не определяет награду и правильность ответа.
- Spring Boot является источником истины для пользователя, попыток, прогресса и рынка.
- PostgreSQL хранит долговременное состояние.
- Gemini может менять только форму объяснения; вопросы и оценивание задаются проверенным серверным каталогом.
- Операции, влияющие на очки или деньги, выполняются на сервере транзакционно.

## 6. Критерии готовности первой версии

Версия считается готовой, когда:

1. Все FR-01–FR-15 проходят ручную приёмку.
2. Серверные автоматические тесты проходят.
3. Полный маршрут из [`ACCEPTANCE_TEST.md`](ACCEPTANCE_TEST.md) выполнен без блокирующих ошибок.
4. WebGL-клиент и API развёрнуты удалённо.
5. В GitHub опубликованы исходники, пользовательские сценарии и UML.
6. Не осталось известных ошибок, приводящих к потере прогресса, двойной награде или чужому доступу.
