# Пользовательские сценарии

## Роли

- **Гость** — пользователь без активной сессии.
- **Игрок** — зарегистрированный пользователь с JWT.
- **Администратор** — игрок с ролью `ADMIN`.
- **Система** — Unity-клиент, Spring API и PostgreSQL.

## Сценарий демонстрационного видео

Ниже приведён рекомендуемый маршрут одного ролика длительностью **4–5 минут**. Он показывает только функции, которые действительно реализованы в текущей версии. Технические названия API и классов в озвучке не нужны: зритель должен увидеть путь пользователя и пользу продукта.

### Подготовка перед записью

1. Запустить PostgreSQL, Spring API, FinStory и Unity-клиент.
2. Проверить, что сервер рынка создал акции, новости и стартовый портфель.
3. Подготовить два аккаунта:
   - новый аккаунт — для короткого фрагмента регистрации;
   - демонстрационный аккаунт — с пройденной диагностикой, серией не менее 7 дней и минимум 2 коинами.
4. Перед записью на демонстрационном аккаунте оставить ежедневные задания невыполненными.
5. Не показывать пароль и служебные окна Unity, Docker или админ-панели в основном ролике.
6. Заранее открыть приложение один раз, чтобы во время записи не было длительной первой загрузки.

### Что не следует заявлять в ролике

- Коины нельзя обменивать на реальные товары, скидки или деньги.
- Из каталога мини-игр полностью работает только «Офис мечты».
- Будущие уровни на дорожке являются визуальными пустышками, а не готовыми уроками.
- Прогресс базовых уроков частично хранится локально; персональные уроки, квизы, задания, серия, коины, рынок и профиль работают через сервер.
- При недоступном учебном API квиз переходит в тренировочный режим и не сохраняет награду.

## US-01. Первый запуск

**Актор:** гость.  
**Предусловия:** сохранённого JWT нет либо сервер отклонил его.  
**Основной поток:**

1. Пользователь запускает сцену `Main`.
2. `AppEntry` инициализирует API и проверяет сохранённую сессию.
3. `ScreenManager` показывает стартовый экран.
4. Пользователь выбирает регистрацию или вход.

**Исключение:** при недоступном сервере стартовый экран остаётся доступным, а сетевое действие показывает ошибку.  
**Результат:** пользователь переходит к US-02 или US-03.

## US-02. Регистрация

**Актор:** гость.  
**Предусловия:** пользователь находится на стартовом экране.  
**Основной поток:**

1. Пользователь вводит никнейм, email, пароль и подтверждение пароля.
2. Unity проверяет заполнение полей и совпадение паролей.
3. `POST /auth/register` создаёт игрока с ролью `PLAYER` и BCrypt-хэшем пароля.
4. Сервер возвращает JWT и идентификатор игрока.
5. Unity сохраняет JWT и открывает онбординг.

**Исключения:** занятый email возвращает `409`; некорректная форма не отправляется; ошибка сети показывается пользователю.  
**Результат:** создана учётная запись и активная сессия.

## US-03. Вход и восстановление сессии

**Актор:** игрок.  
**Предусловия:** учётная запись существует.  
**Основной поток:**

1. Пользователь вводит email и пароль.
2. `POST /auth/login` проверяет пароль и возвращает JWT.
3. Unity сохраняет токен и запрашивает `GET /player/profile`.
4. При следующем запуске `AppEntry` проверяет профиль по сохранённому JWT.
5. При успешной проверке открывается главное меню.

**Исключения:** неверные данные возвращают `401`; просроченный или повреждённый JWT удаляется, после чего показывается стартовый экран.  
**Результат:** пользователь находится в главном меню.

## US-04. Онбординг и интересы

**Актор:** новый игрок.  
**Предусловия:** регистрация завершена.  
**Основной поток:**

1. Пользователь просматривает шаги о дорожке знаний, очках, квизе и бирже.
2. Пользователь может перейти вперёд или пропустить информационные шаги.
3. На последнем шаге пользователь вводит интересы.
4. Unity отправляет `POST /player/interests`.
5. Сервер сохраняет классифицированные интересы либо fallback-значение.
6. Unity запускает диагностический квиз.

**Исключение:** при недоступном классификаторе основной игровой маршрут продолжает работать.  
**Результат:** интересы сохранены, начат US-05.

## US-05. Диагностический квиз

**Актор:** новый игрок.  
**Предусловия:** пользователь авторизован и не завершил диагностику.  
**Основной поток:**

1. Unity отправляет `POST /learning/attempts` с `diagnostic=true`.
2. Сервер создаёт попытку и возвращает 11 вопросов — по одному для каждой темы — без правильных индексов.
3. Пользователь отвечает на каждый вопрос.
4. Каждый ответ отправляется в `POST /learning/attempts/{id}/answers`.
5. Сервер фиксирует ответ и возвращает результат с объяснением.
6. После всех вопросов Unity вызывает `POST /learning/attempts/{id}/finish`.
7. Сервер рассчитывает результат, начисляет новые очки и создаёт персональный урок по слабой теме.

**Исключения:** изменение уже принятого ответа отклоняется; незавершённую попытку нельзя завершить; повторный `finish` не начисляет очки второй раз. При недоступном API запускается локальная тренировка без награды.  
**Результат:** диагностика и персональный урок сохранены.

## US-06. Тематический квиз

**Актор:** игрок.  
**Предусловия:** пользователь авторизован и выбрал тему.  
**Основной поток:**

1. Игрок выбирает тему в разделе уроков.
2. Unity создаёт попытку с `topicId`.
3. Сервер выдаёт вопросы выбранной темы.
4. Игрок отвечает и получает объяснения.
5. Сервер сохраняет результат и начисляет очки только за впервые освоенные вопросы.

**Результат:** обновлены очки и прогресс темы.

## US-07. Персональный разбор и повторение

**Актор:** игрок.  
**Предусловия:** после квиза создан `PersonalLesson`.  
**Основной поток:**

1. После завершения серверного теста Unity получает идентификатор созданного `PersonalLesson`.
2. На итоговом окне игрок нажимает «Открыть разбор →».
3. Unity переходит в раздел уроков, вызывает `GET /learning/lessons` и автоматически открывает созданный материал по его идентификатору.
4. Интерфейс показывает историю, объяснение, пример, термины и шпаргалку.
5. Игрок запускает повторный тест по `lessonId`.
6. Сервер подбирает вопросы слабой темы, по возможности отличные от исходной попытки.
7. При результате не ниже 50% урок помечается завершённым.

**Исключение:** если активный сервис генерации персонального материала недоступен, отображается сохранённый серверный fallback. В текущей конфигурации основным генератором является FinStory; генератор не определяет правильные ответы и не начисляет очки.  
**Ограничение интерфейса:** список ранее созданных персональных уроков сейчас скрыт в новой энциклопедии; штатный видимый маршрут к разбору существует через итоговое окно теста.

**Результат:** слабая тема повторена, статус урока обновлён.

## US-08. Просмотр профиля и прогресса

**Актор:** игрок.

**Предусловия:** пользователь авторизован.
**Основной поток:**

1. Unity запрашивает профиль и учебный прогресс.
2. Игрок видит никнейм, email, уровень, очки, интересы и стоимость портфеля.
3. Игрок может повторно открыть форму интересов и сохранить изменения.
4. Игрок может повторно открыть пятишаговое приветствие.
5. При выходе локальный JWT удаляется и открывается стартовый экран.

**Результат:** профиль отображён либо сессия завершена.

## US-09. Учебная биржевая операция

**Актор:** игрок.  
**Предусловия:** пользователь авторизован, рынок и акции инициализированы.  
**Основной поток:**

1. Unity загружает состояние рынка, акции, новости и портфель.
2. Игрок выбирает акцию, тип операции и количество.
3. `POST /market/order` проверяет деньги или открытую позицию.
4. Сервер изменяет баланс и позицию, создаёт запись `MarketOrder`.
5. Unity получает обновлённый портфель.

**Исключения:** недостаток денег, акций или позиции приводит к отказу без частичного изменения данных; некорректное количество отклоняется.  
**Результат:** операция `BUY`, `SELL`, `SHORT` или `COVER` атомарно сохранена.

## US-10. Рейтинг

**Актор:** игрок.  
**Предусловия:** рынок и пользователи существуют.  
**Основной поток:**

1. Unity вызывает `GET /market/leaderboard`.
2. Сервер рассчитывает стоимость: наличные плюс рыночная стоимость позиций.
3. Интерфейс показывает подиум, список и выделяет текущего игрока.

**Результат:** отображён актуальный рейтинг виртуального капитала.

## US-11. Администрирование

**Актор:** администратор.  
**Предусловия:** зарегистрированному аккаунту назначена роль `ADMIN`.  
**Основной поток:**

1. Администратор входит через `/admin.html`.
2. JWT передаётся в защищённые запросы `/admin/**`.
3. Администратор просматривает профиль, роль, валюты, прогресс, серию и агрегированную статистику игрока.
4. Администратор изменяет редактируемые данные аккаунта, добавляет тестовые дни к серии или сбрасывает отметки о наградах.
5. Администратор меняет интервал рынка или пропускает игровые дни.
6. Администратор управляет старым каталогом вопросов.

**Исключение:** роль `PLAYER` получает `403`; публичного повышения роли нет.  
**Результат:** административное изменение сохранено и доступно клиентам.

## US-12. Ежедневная серия и задания

**Актор:** игрок.

**Предусловия:** пользователь авторизован.

**Основной поток:**

1. При открытии главного меню Unity вызывает `GET /daily`.
2. Сервер создаёт или обновляет запись активности для текущего календарного дня.
3. Последовательный день увеличивает серию, а пропуск начинает новую серию с одного дня.
4. Раздел заданий показывает «Пройти 1 тест» и «Сыграть 1 раз в мини-игру».
5. При первом успешном завершении теста сервер устанавливает прогресс теста `1/1`.
6. Повторный `finish` той же попытки и следующие тесты в этот день не увеличивают счётчик выше `1/1`.
7. Первый клик в «Офисе мечты» вызывает `POST /daily/minigame-completed` и завершает второе задание.
8. Верхняя панель показывает текущую серию и баланс коинов из серверного ответа.

**Результат:** серия и прогресс текущего дня сохранены в PostgreSQL и одинаковы на всех устройствах.

## US-13. Просмотр каталога мини-игр

**Актор:** авторизованный игрок.

**Основной поток:**

1. Игрок выбирает пункт «Игры» в нижней навигации главного меню.
2. Unity строит список карточек из `MiniGameCatalog`.
3. Каждая карточка показывает название, краткое описание, длительность и статус готовности.
4. Карточка «Офис мечты» открывает экран кликера с одной большой кнопкой.
5. Нажатие увеличивает локальный счётчик текущей игровой сессии.
6. Первый клик отмечает ежедневное задание через `DailyService`.
7. Для ещё не реализованных игр кнопка запуска недоступна; отдельные игровые сцены можно подключать через `GameManager`.

**Результат:** пользователь видит доступные и запланированные мини-игры, а разработчик может расширять каталог отдельными определениями и сценами.

## US-14. Награды за серию и обмен коинов

**Актор:** авторизованный игрок.

**Предусловия:** серверный ежедневный прогресс доступен.

**Основной поток:**

1. Игрок нажимает счётчик серии в верхней панели.
2. Unity показывает награды за 7 и 14 дней: коины и виртуальные деньги учебной биржи.
3. Если нужная длина серии достигнута, игрок получает награду через `POST /daily/streak-rewards/{days}/claim`.
4. Сервер проверяет достижение порога и отсутствие повторного получения, затем атомарно обновляет балансы.
5. Игрок открывает окно коинов и обменивает 1 коин через `POST /daily/coins/exchange`.
6. Сервер списывает 1 коин и добавляет `1000 ₸` к виртуальному биржевому балансу.

**Исключения:** закрытая или уже полученная награда отклоняется; при нулевом балансе обмен недоступен.

**Результат:** обновлённые коины и виртуальный баланс отображаются в Unity и сохраняются в PostgreSQL.
