# Персональные уроки: первый рабочий сценарий

После регистрации Unity запускает вводный тест (4 вопроса, по одному на тему). Его можно позже открыть из раздела «Твои уроки», если пользователь вышел до завершения. Это предварительная оценка: точность по теме отображается числом правильных ответов из последних 20, без утверждения о полном освоении.

Spring выдаёт снимок вопросов без правильных ответов. Каждый выбор отправляется на сервер и становится неизменяемым. После получения подтверждения Unity показывает правильный вариант и объяснение. Завершение попытки сохраняет разбор по слабой теме. В Unity карточка появляется в «Твои уроки → Лично для тебя». Кнопка проверки запускает 3 вопроса по этой теме; сначала выбираются вопросы, отсутствовавшие в исходной попытке. Если доступных новых вопросов недостаточно, часть повторяется. После успешной проверки исходная карточка получает отметку «Закреплено».

## API (JWT обязателен)

- `POST /learning/attempts` — `{ "diagnostic": true }`, `{ "topicId": "lesson_savings" }` или `{ "lessonId": "ID персонального урока" }`.
- `POST /learning/attempts/{id}/answers` — `{ "questionId": "...", "selectedIndex": 0 }`; возвращает проверку и объяснение. Повтор того же ответа безопасен; замена ответа возвращает 409.
- `POST /learning/attempts/{id}/finish` — после всех ответов. Повторное завершение возвращает тот же результат и не создаёт повторную награду/урок.
- `GET /learning/lessons` — только уроки владельца JWT.
- `GET /learning/profile` — завершение вводного теста и статистика по темам.

Начисление: +10 в профиль за впервые правильно решённый вопрос. `score` — результат квиза, `awardedScore` — фактически начисленная награда. История и блокировка строки игрока предотвращают двойное начисление при параллельных запросах. Старый `PUT /player/progress` больше не принимает клиентские очки (409). Старые `/questions` пока сохранены для совместимости административного интерфейса; новый учебный сценарий их не использует.

## Gemini

Настроить на сервере переменные `GEMINI_API_KEY` и `GEMINI_MODEL` (имя доступной в аккаунте модели с поддержкой structured output). Ключ не передаётся в Unity. Затем перезапустить Spring с локальным профилем обычным способом. Конфигурация допускает пустые значения: без Gemini весь сценарий работает на проверенном разборе ошибок.

При включённом Gemini в БД записывается статус `PENDING` и сразу доступный учебный разбор. Worker раз в 5 секунд дополняет его объяснением по проверенному материалу, ответам текущей попытки и недавней статистике. Не передаются email, имя или ID игрока. Есть тайм-аут 25 секунд, проверка JSON и ограничения длины; при сбое остаётся `FALLBACK`. Успех — `READY`. Урок сохраняется и не генерируется снова при открытии. Пока есть кнопка ручного обновления списка, без фонового polling в Unity.

Формат ответа Gemini: `title`, `explanation`, `example`, `cheatSheet`. Основан на structured output Generate Content API: https://ai.google.dev/gemini-api/docs/generate-content/structured-output . Проверка формата не гарантирует фактическую точность: перед публичным релизом нужна содержательная проверка AI-разборов. AI не генерирует оцениваемые вопросы в этой версии.

## Данные и развитие

Таблицы `learning_attempts` и `personal_lessons` создаются миграциями Flyway; Hibernate проверяет схему через `ddl-auto=validate`. Попытка хранит версию вопросов и выбранные ответы как JSON, поэтому правки банка не меняют старый результат. Банк и проверенные правила — `learning/LearningCatalog.kt`; ID вопроса содержит версию. Сейчас 16 вопросов, 4 темы. При изменении смысла вопроса меняйте ID.

Очередь генерации рассчитана на один экземпляр Spring. Для нескольких экземпляров потребуется атомарное получение задания/lease. Первую версию сознательно ограничиваем маленьким проверенным банком; следующая работа — больше вопросов, отдельные навыки внутри темы, контроль AI-контента и отложенное повторение.

При недоступности учебного API Unity явно включает тренировку: очки в профиль, персональный разбор и прохождение урока не сохраняются. Ошибка ответа онлайн оставляет тот же выбранный вариант для безопасного повторного запроса. Ошибка завершения оставляет кнопку повторного сохранения.

## Проверка

`./gradlew test` — 8 проверок (контекст и 7 интеграционных сценариев), тесты запускаются на H2, не на рабочей БД. Проверяются HTTP/JWT, отсутствие правильных ответов в выдаче, неизменяемость выбора, изоляция пользователей, разбор ошибок, повторный тест, идемпотентное параллельное завершение и сохранность готового урока при fallback.

В ходе внедрения дополнительно проверен полный HTTP-сценарий на локальном PostgreSQL: вводный тест, параллельное завершение без двойного начисления, персональный урок и новый повторный тест. Временная учётная запись проверки удалена. Реальный вызов Gemini требует ключа и ещё не проверен; проверены формат ответа и поведение при отсутствии ключа.
